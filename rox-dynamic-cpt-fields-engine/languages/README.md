# Translating Dynamic Fields Engine

This plugin is translation-ready. Strings come from PHP and the React admin UI.

## Quick start (Loco Translate or Poedit)

1. Install [Loco Translate](https://wordpress.org/plugins/loco-translate/) or use Poedit.
2. Go to **Loco Translate → Plugins → Dynamic Fields Engine**.
3. Click **New language**, choose your locale (e.g. Bengali → `bn_BD`).
4. Translate the strings and save.

Loco Translate generates both:
- `rox-dynamic-cpt-fields-engine-{locale}.mo` (PHP strings)
- `rox-dynamic-cpt-fields-engine-{locale}-rdcfe-admin-app.json` (React admin UI)

## Manual workflow (WP-CLI)

From the plugin root:

```bash
# 1. Extract PHP + React admin strings into the template file
npm run make-pot

# 2. Copy the template and translate (Poedit, or edit .po by hand)
cp languages/rox-dynamic-cpt-fields-engine.pot languages/rox-dynamic-cpt-fields-engine-bn_BD.po

# 3. After translating the .po file, generate runtime files
npm run make-json
```

This creates:
- `rox-dynamic-cpt-fields-engine-bn_BD.mo` — PHP translations
- `rox-dynamic-cpt-fields-engine-bn_BD-*.json` — JavaScript (React) translations

## File naming

| File | Purpose |
|------|---------|
<<<<<<< Updated upstream
| `rox-dynamic-cpt-fields-engine.pot` | Template with all source strings (PHP + React admin) |
=======
| `rox-dynamic-cpt-fields-engine.pot` | Template with all source strings |
>>>>>>> Stashed changes
| `rox-dynamic-cpt-fields-engine-{locale}.po` | Your translation (editable) |
| `rox-dynamic-cpt-fields-engine-{locale}.mo` | Compiled PHP translations |
| `rox-dynamic-cpt-fields-engine-{locale}-*.json` | React admin translations |

**Text domain:** `rox-dynamic-cpt-fields-engine`

The POT filename **must** match the text domain. WordPress.org ignores mismatched template files and falls back to auto-extracting PHP strings only (~255 strings instead of the full ~2,200+).

## translate.wordpress.org

Community translations at [translate.wordpress.org](https://translate.wordpress.org/) rely on the committed POT file and the built admin bundle:

1. **`languages/rox-dynamic-cpt-fields-engine.pot`** must be included in each release (generated by `npm run build` or `npm run make-pot`).
2. React admin strings reference **`assets/build/main.js`** (stable filename) so JSON translation files match `wp_set_script_translations()`.
3. TypeScript sources under `assets/admin/src/` are development-only; WP-CLI cannot scan `.ts`/`.tsx`, so the custom `scripts/make-pot-js.mjs` step merges React strings into the POT after PHP extraction.

After updating the POT, commit it to SVN trunk so GlotPress picks up new strings on the next import.

## Notes for translators

- `%s`, `%d`, `%1$s` etc. are placeholders — keep them in the same order.
- Strings like `publish`, `draft`, slugs, and API keys are technical and usually stay in English.
- After updating translations, reload the WordPress admin to see React UI changes.
